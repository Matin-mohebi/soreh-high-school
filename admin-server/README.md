# سرویس مدیریت دبیرستان سوره (admin-server)

سرویس کوچک Node.js **بدون هیچ وابستگی خارجی** که سه کار انجام می‌دهد:

1. **احراز هویت واقعی مدیر** (نام کاربری/رمز هش‌شده با scrypt + نشست کوکی HttpOnly)
2. **انتشار تغییرات پنل به مخزن GitHub** (GitHub Contents API) → GitHub Actions خودکار سایت را بازسازی می‌کند
3. **سرو کردن سایت با محتوای لحظه‌ای** + ثبت‌نام/ورود بازدیدکنندگان + مدیریت رسانه و کاربران

## راه‌اندازی سریع

```bash
# ۱) پیش‌نیاز: Node.js نسخه ۱۸ به بالا

# ۲) ساخت سایت (یک بار)
cd ..            # ریشه‌ی مخزن
npm run build    # خروجی در dist/

# ۳) تنظیمات سرویس
cd admin-server
cp .env.example .env

# ۴) ساخت هش رمز مدیر و قرار دادن آن در .env
node server.js hashpass «رمز-مورد-نظر»

# ۵) کلید امضای نشست
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"

# ۶) (برای انتشار خودکار) توکن GitHub با دسترسی Contents: RW روی همین مخزن
#    GitHub → Settings → Developer settings → Fine-grained personal access tokens

# ۷) اجرا
node server.js
# پنل:  http://localhost:8787/admin/
# سایت: http://localhost:8787/
```

پس از اجرا، پنل مدیریت (`/admin/`) به‌صورت خودکار «حالت متصل» می‌شود و دکمه‌های **انتشار** فعال می‌شوند. انتشار = commit فایل‌های `content/*.json` به مخزن؛ GitHub Actions طی ۱ تا ۲ دقیقه سایت عمومی را بازسازی می‌کند.

## معماری انتشار (چرا این شکل؟)

GitHub Pages فقط فایل استاتیک سرو می‌کند و **نمی‌تواند** PHP/MySQL اجرا کند. بنابراین:

```
پنل مدیریت → admin-server (احراز هویت + اعتبارسنجی) → GitHub API (commit)
   → GitHub Actions (build) → GitHub Pages (سایت عمومی)
```

- توکن GitHub **فقط** داخل `admin-server` (متغیر محیطی) زندگی می‌کند و هرگز به مرورگر فرستاده نمی‌شود.
- پنل روی میزبانی استاتیک (GitHub Pages) به‌صورت «پیش‌نمایش محلی» کار می‌کند و صادقانه برچسب Prototype دارد.

## نکات امنیتی

- `.env` و `data/` در `.gitignore` هستند و هرگز commit نمی‌شوند.
- کوکی نشست: `HttpOnly; SameSite=Strict` (+`Secure` پشت پروکسی HTTPS).
- ورود مدیر: محدودسازی نرخ (۱۰ تلاش در ۵ دقیقه).
- همه‌ی درخواست‌های تغییر وضعیت: بررسی Origin + هدر `X-Requested-With`.
- آپلود رسانه: سفید‌لیست فرمت + سقف ۲ مگابایت + نام فایل ایمن.
- رمز کاربران سایت: scrypt با salt تصادفی؛ هش‌ها هرگز از API برگردانده نمی‌شوند.
- برای استفاده‌ی عمومی، سرویس را پشت HTTPS قرار دهید (مثلاً Nginx/Caddy یا یک سرویس رایگان مانند Render/Fly).

## نقاط پایانی API

| مسیر | متد | توضیح |
|---|---|---|
| `/api/session` | GET | وضعیت نشست مدیر |
| `/api/login` | POST | ورود مدیر |
| `/api/logout` | POST | خروج |
| `/api/content` | GET | محتوای فعلی (همه فایل‌ها) |
| `/api/content/{name}` | PUT | اعتبارسنجی + ذخیره + commit |
| `/api/preview` | POST | رندر HTML صفحه اصلی از داده‌ی دلخواه |
| `/api/media` | POST | بارگذاری رسانه (base64) |
| `/api/media/{file}` | DELETE | حذف رسانه |
| `/api/users` | GET | فهرست کاربران سایت (بدون هش) |
| `/api/users/{id}` | DELETE | حذف کاربر |
| `/api/logs` | GET | گزارش فعالیت |
| `/auth/register` `/auth/login` | POST | فرم‌های عمومی سایت |

## محدودیت‌ها

- نشست‌ها در حافظه هستند؛ ری‌استارت سرویس = ورود مجدد (برای مدرسه کافی است).
- اگر چند مدیر هم‌زمان از نسخه‌های محلی مختلف ویرایش کنند، آخرین commit برنده است.
- این سرویس برای یک مدرسه‌ی کوچک طراحی شده؛ برای مقیاس بزرگ‌تر نیاز به بازطراحی دارد.
