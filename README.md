# دبیرستان سوره — وب‌سایت رسمی | Soreh High School

وب‌سایت رسمی **دبیرستان سوره (Soreh High School)** — مهاجرت‌یافته از وردپرس (قالب Class Stars + افزونه Class Stars Toolkit) به یک معماری دو-بخشی:

| بخش | فناوری | محل استقرار |
|---|---|---|
| 🌐 **سایت عمومی استاتیک** (پوشه `site/`) | HTML/CSS/JS خالص + `content.json` | **گیت‌هاب پیجز** — رایگان |
| 🛠 **پنل مدیریت + سایت زنده** (Next.js 16) | TypeScript، Prisma، SQLite | سرور مدیریت (پیش‌نمایش فعلی یا هاست رایگان مثل Vercel) |

- **نشانی سایت عمومی:** https://matin-mohebi.github.io/soreh-high-school/
- **پنل مدیریت:** مسیر `/admin` روی سرویس مدیریت
- **نام کاربری / رمز عبور پیش‌فرض:** `admin` / `admin` — ⚠️ پس از نخستین ورود از بخش «کاربران و دسترسی‌ها» تغییرش دهید.

---

## ۱. معماری انتشار (چگونه تغییرات پنل به سایت می‌رسد)

گیت‌هاب پیجز فقط فایل استاتیک سرو می‌کند و به دیتابیس دسترسی ندارد؛ بنابراین:

```
پنل مدیریت (ویرایش محتوا)
        │  دکمه «انتشار تغییرات»
        ▼
ساخت content.json از دیتابیس + کپی رسانه‌ها
        │  GitHub Contents API (توکن فقط سمت سرور)
        ▼
کامیت در همین مخزن (site/assets/content.json + site/uploads/)
        │  GitHub Actions (deploy-pages.yml)
        ▼
انتشار خودکار در https://matin-mohebi.github.io/soreh-high-school/
```

علاوه بر این، نسخه **زنده** (سرویس Next.js) محتوا را مستقیم از دیتابیس رندر می‌کند؛ یعنی هر چیزی که در پنل ثبت شود **بی‌درنگ** در سایت زنده دیده می‌شود و انتشار استاتیک فقط برای نسخه گیت‌هاب‌پیجز لازم است.

## ۲. ساختار مخزن

```
├── site/                     ← سایت استاتیک قابل انتشار در گیت‌هاب پیجز
│   ├── index.html            صفحه اصلی (دروازه ورود، هیرو، آمار، مدیران، برترین‌ها، اخبار)
│   ├── news.html             اخبار و اطلاعیه‌ها
│   ├── page.html?slug=…      برگه‌های ایستا
│   ├── schedule.html         برنامه هفتگی
│   ├── contact.html          فرم تماس
│   ├── login.html / register.html
│   └── assets/               css + js + content.json + uploads (رسانه‌ها)
├── src/                      ← سرویس مدیریت (Next.js 16 App Router)
│   ├── app/(site)/           سایت زنده (رندر سمت سرور از دیتابیس)
│   ├── app/admin/            پنل مدیریت
│   └── app/api/              APIهای REST (احراز هویت، محتوا، رسانه، پیام، انتشار)
├── prisma/schema.prisma      مدل دیتابیس (SQLite)
├── scripts/                  ابزارهای کمکی (ساخت CSS، انتشار، بذر محتوا)
├── wordpress-source/         📦 سورس دست‌نخورده وردپرس (قالب + افزونه + zips اصلی)
└── .github/workflows/        استقرار خودکار گیت‌هاب پیجز
```

## ۳. امکانات پنل مدیریت (همگی واقعی و متصل به دیتابیس)

- **پیشخوان:** آمار زنده، آخرین فعالیت‌ها، میانبرها
- **محتوا:** مدیر و معاونان، دانش‌آموزان برتر، اخبار و اطلاعیه‌ها، برگه‌ها، منوی سایت، برنامه هفتگی
- **رسانه و پیام‌ها:** کتابخانه رسانه (بارگذاری/حذف)، پیام‌های فرم تماس (خوانده/نشده)
- **سیستم:** تنظیمات کامل متن‌ها (معادل ۱۵ فیلد Customizer قالب)، سئو، کاربران و نقش‌ها، گزارش فعالیت
- **انتشار:** بسته ZIP استقرار + ارسال مستقیم به مخزن گیت‌هاب
- جست‌وجو، صفحه‌بندی، اعتبارسنجی فارسی، دیالوگ تأیید برای عملیات مخرب، حالت روشن/تاریک

### امکانات افزونه Class Stars Toolkit (پورت کامل)
- جست‌وجوی زنده در کارت‌ها با نرمال‌سازی فارسی (ی/ک عربی، ارقام فارسی، نیم‌فاصله)
- نوار پیشرفت مطالعه + دکمه سه‌بعدی «بازگشت به بالا»
- دروازه ورود نشست‌محور + انیمیشن ظهور + شمارنده آمار با ارقام فارسی (پورت app.js قالب)

## ۴. اجرای سرویس مدیریت (به‌روزرسانی و نگهداری)

```bash
# پیش‌نیاز: Node 20+ (یا Bun) و SQLite
npm install            # یا: bun install
cp .env.example .env   # و پر کردن مقادیر (بخش ۵)
npx prisma db push     # ساخت جداول
npm run dev            # اجرای توسعه روی پورت 3000
```

دیتابیس SQLite در پوشه `db/` ساخته می‌شود. حساب مدیر با نام کاربری `admin` و رمز `admin` ساخته می‌شود (اسکریپت `scripts/reset-admin-password.cjs` برای بازنشانی رمز).

### تنظیم محیط (.env)

| متغیر | توضیح |
|---|---|
| `DATABASE_URL` | مسیر فایل SQLite، مثل `file:/path/to/db/custom.db` |
| `GITHUB_TOKEN` | توکن دسترسی شخصی با دسترسی `repo` — **فقط سمت سرور**، هرگز در کد کلاینت نیست |
| `GITHUB_REPO` | مثل `Matin-mohebi/soreh-high-school` |
| `GITHUB_BRANCH` | شاخه انتشار، مثل `migration/soreh-school` |
| `GITHUB_CONTENT_PATH` | `site/assets/content.json` |
| `GITHUB_PUSH_MEDIA` | `1` برای همگام‌سازی رسانه‌ها به `site/uploads/` |
| `CORS_ORIGINS` | برای نسخه استاتیک: آدرس سایت پیجز (اجازه فراخوانی API از دامنه دیگر) |

> ⚠️ **امنیت توکن:** توکن گیت‌هاب و رمزها فقط در `.env` سمت سرور نگهداری می‌شوند و `.env` در `.gitignore` است. هرگز توکن را در فایل عمومی یا کد کلاینت قرار ندهید. اگر توکنی جایی افشا شد، از تنظیمات گیت‌هاب حتماً باطل (Revoke) و توکن جدید بسازید.

## ۵. استقرار سرویس مدیریت (رایگان)

گیت‌هاب پیجز فقط بخش استاتیک را سرو می‌کند؛ برای پنل مدیریت و سایت زنده به یک هاست Node.js رایگان نیاز است:

- **Vercel** (پیشنهادی): مخزن را وصل کنید، متغیرهای `.env` را در تنظیمات پروژه وارد کنید و `db/` را روی یک دیسک پایدار یا SQLite Serverless (مثل Turso) تنظیم کنید.
- **Render / Railway / Fly.io** (پلن رایگان): اجرای `npm run build && npm start` با دیسک پایدار برای دیتابیس.

تا زمان راه‌اندازی سرویس روی هاست عمومی، نسخه استاتیک گیت‌هاب‌پیجز مستقل کار می‌کند (فرم تماس/ورود در نسخه استاتیک با پیام راهنما غیرفعال‌اند تا داده جعل نشود).

## ۶. گردش کار روزانه مدیر

1. وارد پنل شوید (`/admin` → `admin` / `admin`)
2. محتوا را ویرایش کنید (خبر، برگه، پیام‌ها، تنظیمات…)
3. تغییرات فوراً در «سایت زنده» قابل مشاهده است (لینک کره 🌐 بالای پنل)
4. برای به‌روزرسانی نسخه گیت‌هاب‌پیجز: **انتشار در سایت ← انتشار تغییرات**

## ۷. سلب مسئولیت محتوا

آمار صفحه اصلی (۱۲۰۰ دانش‌آموز، ۸۰ معلم، ۲۵ سال سابقه) و اخبار نمونه، **مقادیر پیش‌فرض خود قالب Class Stars** هستند؛ مدیر مدرسه باید آن‌ها را از پنل مدیریت با اطلاعات واقعی جایگزین کند. آدرس، تلفن و لوگوی رسمی مدرسه به عمد خالی نگه داشته شده‌اند تا اطلاعات جعلی منتشر نشود.
